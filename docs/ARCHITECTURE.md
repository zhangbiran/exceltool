# 架构说明

## 选择

首版使用 Python CLI 和 LibreOffice UNO。LibreOffice 是统一的 `.xls/.xlsx`
读写引擎；Python 负责参数、操作语义、输出安全和验证。

选择原因是纯 Go 生态没有成熟的旧版 `.xls` 写入实现，而当前运行环境已具备
LibreOffice 和 `python3-uno`。代价是存在外部进程依赖，保存时也可能重写文件
内部结构，因此验收采用逻辑级往返验证。

## 模块

- `cli.py`：命令、参数、JSON、退出码。
- `engine.py`：启动隔离 LibreOffice、UNO 连接、工作簿读写与低层操作。
- `operations.py`：查看、查找、矩阵/范围、sheet、行和列的用户语义。
- `fonts.py`：通过 fontconfig 精确检查请求字体与系统解析字体。
- `editing.py`：临时副本、原子发布和写后验证。
- `patching.py`：Patch v1 严格校验、顺序分派、失败定位和最终状态验证计划。
- `safety.py`：输入 SHA256、公式快照、声明范围策略、差异定位和验证报告。

首版保持少量模块，避免为单一引擎建立复杂插件体系。若未来加入第二种引擎，再
抽象公共接口。

二维 JSON 是命令层的稳定数据边界：空值、数字、布尔、文本和公式由统一编解码
规则转换，不暴露 UNO 的 `CellContentType`。裸 JSON 用于单 sheet 管道，带元数据
JSON 用于审计和多 sheet 查看。每次调用只打开一个工作簿；公式管道按文本保存，
结构复制交由 UNO `copyRange`。
`view --tail N` 在每个 sheet 读取其有效区域后计算最后 N 行，因此多 sheet 查询
不会错误复用第一个 sheet 的行边界；列范围仍按普通 `--cols` 解析。
`sheet info` 复用同一有效区域计算，以只读方式返回一个或全部 sheet 的范围、行列数
和最后行列，不保存工作簿。只有格式的尾部单元格可能被 LibreOffice 计入有效区域。
样式元数据只附加到 json-full；文本单元格的字体字号通过整段 text cursor 写入，
避免 LibreOffice 保存已有文本时丢失字符属性。验证按内容脚本选择相关字体槽，
并保留三个字体脚本槽的实际值以展示回退。
单格不建立独立编辑协议：`write` 的一格二维数组、`clear --range CELL` 和
`style --range CELL` 分别复用矩阵写入与范围编辑路径。

## 写入流程

1. 校验输入、可选 SHA256、目标和输出模式。
2. 在临时目录复制输入文件，并确认副本 SHA256 与初始输入一致。
3. 使用独立 LibreOffice 用户配置打开副本，记录原始公式快照。
4. 执行一个明确操作；非结构操作核对声明范围外公式，再记录保存前公式快照。
5. `.xls` 保存前按 `FormulaResultType2` 原样重赋字符串结果的普通公式，并再次核对
   全部公式文本；字符串结果数组公式不能安全逐格处理时拒绝保存。
6. 保存为原格式并重新打开，先核对全部最终公式，再验证目标操作结果。
7. 就地发布前重新核对原路径 SHA256；验证成功后发布到 `--out`，或原子替换
   输入文件。备份由调用者在命令外显式决定。

Patch 复用同一写入流程，但第 4 步在一个 workbook 实例上按数组顺序执行多个
操作。操作完成后生成最终验证计划；计划只比较稳定的逻辑契约，不比较
LibreOffice 保存时可能规范化的内部直接样式表示。行操作和 sheet 复制验证最终
内容、公式、有效样式与行高，明确样式和硬样式清除验证目标单元格，sheet 名称及
顺序验证结构；列操作还验证最终列宽。`.xls/.xlsx` 的列宽存储单位不同，重开验证
允许 0.1 mm 的格式量化误差。整个 patch 仍只调用一次 `save` 和一次只读重开。

公式快照通过 UNO `queryContentCells(FORMULA)` 查询公式区域，不按有效区逐格
全量扫描。普通 write/clear 将明确内容目标加入允许变化集合；style 和
col.autofit 不允许操作阶段改变公式。包含 sheet/行/列结构操作的 Patch 首版不做
原始坐标到最终坐标的通用语义映射，但保存前最终公式到重开状态仍必须逐个一致。

列宽自适应通过 UNO `OptimalWidth` 计算后立即施加毫米上限，只在显式
`col autofit` 或 `col.autofit` patch 操作中发生。`find` 和 `view` 通过同一
`resolve_window` 路径解析行、列、矩形、末尾及正方区域；`find` 只读遍历选定
sheet 的解析结果，不修改、保存或发布工作簿。

`find --regex` 使用 Python 标准 `re` 的 `search` 语义，并与普通 `find`、`view`
复用完全相同的 sheet 和范围规则。命令层在启动 LibreOffice 前预编译表达式；
调用者根据工作簿大小自行决定是否缩小范围。标准 `re` 不提供可靠的单次匹配超时，
因此文档要求使用简单正则并避免容易产生灾难性回溯的写法。

列宽 JSON 同时保留操作时的 `width_mm` 和重开后的 `actual_width_mm`。Patch 的
验证计划会跟踪后续列插入、删除和复制造成的坐标移动，通过 `final_column` 报告
最终位置；已被后续操作删除的列用 `null` 明确表示，不伪造实际宽度。

## 故障

- `2` 参数错误。
- `3` 文件或 sheet/range 目标错误。
- `4` 格式或功能不支持。
- `5` LibreOffice 编辑或保存失败。
- `6` 写后验证失败。

错误不触发另一引擎、格式转换或伪成功。
